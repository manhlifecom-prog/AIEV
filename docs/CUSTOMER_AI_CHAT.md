# Conversational video assistant — Windows 0.5.0

Customers can discuss an idea before selecting a source. `/api/customer/assistant` uses OpenAI structured decisions (`reply` or `prepare`), the last 24 conversation messages and the latest completed/pending source request. Greetings and clarification do not open a file picker. Supported edit requests prepare a quote in the native app. Further edits reuse the locally stored source and the resolved cumulative request.

Website, Android wrapper and iPhone PWA can chat; rendering requires the Windows app. Windows 0.3.0 remains compatible with individual files; 0.4.0 adds shared Drive folders and merged sources. 0.5.0 adds native streamed chat and device activity events. Existing Windows 0.2.0 users must update. Sources and output videos stay on the customer's device. Audio transcription and edit planning still use the shared authenticated AI API. See [Drive folders](CUSTOMER_DRIVE_FOLDERS.md) for folder sharing, pagination and update instructions.

Customer chat costs **1 service token per AI message**, deducted atomically. Completed turns are cached by owner/request ID. Upstream failure refunds the chat token once and does not append a misleading assistant response. Video rendering retains its separate quoted cost and prior refund policy. Saying “đồng ý” after a quote in Windows starts rendering; “hủy” cancels a pending quote. Those exact control commands do not invoke or charge chat AI. Authenticated admins are exempt from chat/render token charges; see [admin billing and operations](CUSTOMER_ADMIN.md).

Available operations remain source cuts/reordering, aspect ratio, original-language speech captions, title and removal of speech pauses. AI does not generate arbitrary new scenes, add music, translate captions or run arbitrary commands. Context is bounded; it is not the complete Codex coding agent.

Verified locally: authenticated billing/ownership/history/refund integration tests, real OpenAI greeting without file selection, initial 4-second square render with captions, confirmation by chat, follow-up revision on the same source without another file picker, and a second completed render. Wallet used for this verification was isolated in memory. No production wallet was funded or charged for tests.

## Responsive chat (0.5.0)

Submit adds the user message immediately and clears the composer. The assistant endpoint accepts optional `stream: true` and sends authenticated SSE accepted/status/reply/result/error events with heartbeats and buffering disabled. Reply text comes from real Responses API deltas; partial plan JSON is never exposed. The existing JSON endpoint remains compatible with Windows 0.3.0/0.4.0. Streaming stops cancel the upstream call and refund unfinished chat once; completed owner/request-ID replays return the stored result without another charge. Retry preserves the original request ID and source thread. Polling cannot replace an in-flight or failed optimistic turn. Navigation and repeated Enter submissions are guarded during a request.

Windows 0.5.0 forwards AI events and real source/download/normalization/transcription/render stages through a limited preload bridge. Stop applies while the AI chat response is unfinished, not to downloading or rendering. Render activity also remains visible after chat confirmation returns. The UI labels native Windows versus browser; a missing bridge in a native user agent produces an actionable connection error instead of silently using web mode. A Windows Chrome/Edge PWA keeps the installer action visible because a web window has no native render engine. Markdown bold/code text is rendered safely without raw HTML.

Verification: 28 server/media tests and 4 desktop stream/preload/security tests; TypeScript and production Next build pass. CUA exercised optimistic submit, stop, same-turn retry and final response formatting with isolated fixture data; 390×844 had no horizontal overflow. A separate controller integration used real OpenAI and bundled FFmpeg: two clips with different dimensions and audio availability, real download/merge activity, a four-second square MP4 and a three-second revision from the reused source. Admin stayed at zero balance. Native IPC was simulated; the actual installed Electron window/installer and full customer folder rendering were not exercised.
